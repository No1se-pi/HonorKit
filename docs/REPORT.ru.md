# HONOR MagicBook Art 14 MRA-XXX на Kali Linux

**Дата** 18 ноября 2026 г.

**Система** Kali Rolling amd64, ядро `6.19.14+kali-amd64`, GNOME 50, Wayland, Intel Core Ultra 5 125H.

## Жесты тачпада

На ноутбуке подтверждены встроенный I²C HID `TOPS0102:00 35CC:0104`, фирменный
отчёт `0x0e` размером 9 байт в HID-дескрипторе и `intel_backlight`.
В GNOME проверены сочетания `Super+H`, `Alt+F4`, `Super+V`, `Print`
и `Shift+Print`. Громкость проверяется через PipeWire/WirePlumber.

- [MadhiasM/honor-magicbook-art-touchpad-gestures](https://github.com/MadhiasM/honor-magicbook-art-touchpad-gestures/tree/25e9750adb8f10b1e1be69d55d803ccddcae2d14) послужил основой сборки. Один процесс на C, единственная зависимость ELF — libc. При аудите обнаружены блокирующее чтение при остановке, вызов syslog в обработчике сигнала, перепривязка к меняющемуся имени hidraw, игнорирование ошибок `ioctl` и записи. В поставляемом unit также одновременно присутствовали динамический поиск hidraw и разрешение только для `/dev/hidraw1`. Отдельный upstream-инструмент `touchpadctl` отправляет настройки в прошивку.
- [ZachAR3/HonorControl](https://github.com/ZachAR3/HonorControl/tree/2f61ef76b1ced234cccb44ee2a2feb8d920ddd6c) содержит Python-реализацию чтения жестов и распознавания HID-дескриптора. Полная конфигурация добавляет привилегированный D-Bus backend, зависимости sdbus и honor-tools, опциональный Qt-интерфейс, аппаратные настройки и экспериментальный WMI-модуль. Локально использован парсер дескриптора из проекта для проверки интерфейса.

Собран и с разрешения установлен демон с проверкой VID/PID и размера отчёта,
фиксированным набором клавиш, проверками записи и остановкой через signalfd.
Файлы службы принадлежат root. Доступ ограничен чтением hidraw тачпада и записью
в `uinput`. Capabilities сброшены. Правило udev привязывает автозапуск к
обнаружению тачпада по HID ID. Исходники, diff, тест и команды отката
находятся в [gesture](../gesture/INSTALL.md).

**Проверки.** Сборка GCC с `-Werror` и hardening; тест UBSan прошёл для девяти
привязок, ошибочных HID-отчётов, последовательностей нажатия/отпускания, ошибок
ввода-вывода и остановки в простое. Unit и udev-правило прошли синтаксическую
проверку. Служба запущена и создала устройство `HONOR MagicBook Art Gesture Keys`.
Первая установка отбрасывала реальные 31-байтные отчёты. Диагностика поймала
102 таких отчёта и ни одного виртуального нажатия. После обновления демон
принимает оба формата, 9 и 31 байт. Повторный замер зафиксировал 70 фирменных
отчётов и 70 соответствующих нажатий. Проверены два направления для каждого
края и открытие интерфейса скриншота. Громкость в проверке менялась с 0,40 до
0,72. Пользователь подтвердил работу жестов. Остальные сочетания покрыты
тестом отображения отчёта в клавиши.

## Сканер отпечатков FPC

USB `10a5:a900`, строка `FPC Sensor Controller L:0002 FW:22.26.2.43`.
Штатные `libfprint 1.94.10` и `fprintd 1.94.5-4+b2` в приватной D-Bus-сессии
вернули пустой список. Для этого USB ID отдельный драйвер отсутствует и в
[официальном списке устройств libfprint](https://fprint.freedesktop.org/supported-devices.html).

- [cityji/honor-magickbookpro-fingerprint-driver](https://github.com/cityji/honor-magickbookpro-fingerprint-driver/tree/8bb3f688b7aa4c8327227f59830f2f8dd96943b3) включает FPC Match-on-Host из [MR 396](https://gitlab.freedesktop.org/libfprint/libfprint/-/merge_requests/396) и исправления захвата, обработки ошибок, раскладки изображения и регистрации. Автор проверял прошивку `22.26.2.29`.
- [benjaminjamesxyz/fingerprint-sensor](https://github.com/benjaminjamesxyz/fingerprint-sensor/tree/c28d1f87904a37891e4c3a5f6a65de1fabf3f875) включает те же основные патчи, дополнительное исправление suspend/resume и упаковку под Arch. В проверенном PKGBUILD имя каталога расходится с именем клона. Поставляемая политика Polkit расширяет права активных участников wheel. В Kali применяется штатная политика Polkit.

Первую сборку выполнил на указанной проектами версии `1.94.6` для проверки
совместимости. Для установки перенёс драйвер на `1.94.10`, версию базы Kali,
upstream-коммит `0c97a47d8ef405cd577b87058c1e89cae9d242e7`. Адаптировал Meson,
оставил в драйвере только PID `a900` и добавил отказ при несовпадении
геометрии `64×176` и HWID `0x331`. Эти параметры проверяются при инициализации
сканера. Патчи и план развёртывания находятся в [fingerprint](../fingerprint/INSTALL.md).
Инструменты и заголовки для сборки были распакованы локально из пакетов Kali.

Источник закрытого `libfpcbep.so` — архив `r1slm02w.zip`, опубликованный Lenovo
для ThinkPad. SHA-256 архива совпала с опубликованной. MD5 извлечённого
бинарника совпала со значением обоих проектов. SHA-256 бинарника
`5daa63bad068a3f97b5bb4d83de4d9fcceed6b4d8f1070ed3a00916abfbf664a`.
Это ELF x86-64, зависимость — libc, стек без права исполнения.
Закрытая реализация и встроенный TLS ограничивают полноту аудита. Патч
раскладки опирается на внутренние смещения конкретной сборки бинарника.
Результаты для `22.26.2.29` служат ориентиром, для `22.26.2.43` требуется
проверка положительного и отрицательного совпадения. [Публикация Lenovo](https://support.lenovo.com/gb/en/downloads/ds563477-fpc-fingerprint-driver-for-ubuntu-2004-ubuntu-2204-thinkpad-e14-gen-4-e15-gen-4)

**Проверки.** Meson/Ninja собрали драйвер, два теста ядра библиотеки прошли,
29 пропущены из-за конфигурации с одним драйвером, отключённого hwdb и отсутствия
компонентов эмуляции. `ldd -r` для бинарника fprintd прошёл, в установленной
частной библиотеке отсутствует RUNPATH в рабочий каталог. С разрешения
поставлены два штатных пакета и drop-in, который направляет только
`fprintd.service` в `/opt/honor-mra-a900/lib`. Обе библиотеки подтверждены
через `/proc/<PID>/maps`. Служба перечисляет `/net/reactivated/Fprint/Device/0`.
Файлы `gdm-fingerprint`, `common-auth` и `sudo` проверены по исходным SHA-256.

Регистрация правого указательного пальца завершилась статусом
`enroll-completed`. Проверка того же пальца вернула `verify-match`, а другого
пальца — `verify-no-match`. Все три результата получены на реальном устройстве
с `FW:22.26.2.43`.

После отдельного согласования установлен `libpam-fprintd 1.94.5-4+b2`.
GDM использует существующий профиль `gdm-fingerprint`. Хеши всех исходных
файлов `/etc/pam.d` совпали, включая `common-auth`, `gdm-password` и `sudo`.
Резервная копия находится в `/var/backups/honor-mra-pam/pam.d` с доступом root.
Интеграция с `sudo` отсутствует.

При проверке экрана блокировки GNOME получил `verify-no-match` для
другого пальца. Совпадение зарегистрированного пальца подтверждено
событием `verify-match` и переходом сеанса в разблокированное состояние.

## Проверка после перезагрузки

После перезагрузки служба жестов запустилась через udev в 14:06:04 МСК.
Счётчик перезапусков равен нулю. Журнал GDM подтвердил вход по отпечатку
через `gdm-fingerprint`. Сохранённый шаблон доступен после активации
`fprintd` через D-Bus.

Первый контрольный запуск `fprintd-verify` после загрузки вернул
`verify-no-match` на шаге зарегистрированного пальца. Повторный проход
вернул `verify-match` для зарегистрированного пальца и `verify-no-match`
для другого. Контрольный сценарий завершился с кодом 0. Одноразовая
запись GNOME для запуска проверки удалилась после первого входа.
Хеши файлов PAM повторно совпали. Парольный профиль GDM сохранён.
Порядок полного удаления указан в [инструкции по сканеру](../fingerprint/INSTALL.md).
Обе инструкции описывают удаление файлов, добавленных в ходе этой работы.
